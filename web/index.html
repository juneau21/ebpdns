缓存策略说明
LRU 分区（默认 · lru）
8 分桶独立锁+OrderedDict，全局共享一个缓存池，实现简单开销低，适合热点集中场景。缺点：一次性查询会污染缓存挤出热点；不同分流 group 的条目互相挤占。
分区 LRU（partitioned）
按分流 group（domestic/global/default 等）隔离独立缓存池，容量按 cache_partitions 比例分配，各 group 互不挤占。适合分流规则多、希望不同流量互不影响的场景。
W-TinyLFU（tinylfu）
Caffeine 风格三段式：window(1%) → probation(20%) → protected(80%) + Count-Min Sketch 频率估计。一次性访问在窗口区即淘汰，高频条目受保护不被挤出，抗扫描污染，命中率通常高 5-15%。额外内存约 512KB。
切换策略后自动热重载重建缓存（已有缓存会清空），建议运行 24 小时对比命中率再决定长期策略。

SmartDNS 式智能解析
用户态数据面 + 可选 eBPF XDP 内核旁路

本应用是仿照 SmartDNS 构建的智能 DNS 解析软件。默认数据面运行在用户态: daemon 监听 UDP/TCP :53(IPv4), IPv6 UDP6/TCP6 需在配置中显式写出地址(默认不开启), 以用户态 LRU 缓存模拟 BPF LRU_HASH Map——查询命中时由 daemon 主线程直接回包(快路径, 响应体预编码), 未命中时进入 SmartDNS 式解析引擎: 六协议上游(UDP/TCP/DoH/DoT/DoH3/DoQ) 多路并发、测速择优、域名分流、CNAME 链展开、TTL 预取, 结果回填 LRU 并落盘持久化。内置 缓存投毒防护(0x20 查询名随机化)、EDNS0 防分片(UDP size 1232)、加密查询填充(RFC8467)、双栈智能(有 A 记录才屏蔽 AAAA, 纯 v6 不误伤)。整套运行无需内核权限。同时保留 eBPF XDP 内核旁路预留接口(bpf/ 目录参考实现), 可在支持原生 XDP 的网卡上把缓存命中下沉到内核直答, 作为进阶加速选项。

实际数据面路径data path
DNS LISTEN

报文入口 (IPv4 + 可选 IPv6)

server.py 监听 UDP4/TCP4 :53; IPv6 UDP6/TCP6 仅当配置显式给出地址(如 [::]:53)才绑定, 默认不监听, 无 IPv6 栈自动跳过仅告警。解析 (qname, qtype) 后主线程查缓存; 命中走快路径直接回包(响应体预编码, 仅重拼 qid), miss 交解析引擎。

LRU MAP

用户态缓存 (模拟 BPF Map)

cache.py 以用户态 LRU 模拟 BPF_MAP_TYPE_LRU_HASH: 存 (qname, qtype) → 答案 + TTL; 支持按分流 group 分区淘汰、TTL 钳制(ttl_min/max + 规则级覆盖)、负缓存(NXDOMAIN)、serve-stale 过期兜底、剩余 TTL 落盘持久化, 重启自动恢复。

RESOLVER

SmartDNS 式解析引擎

  • 域名分流: 精确 / *.通配 / 中缀通配 / re:正则 / forceIp / block (三层哈希索引, 10 万条级 <1ms) + URL 订阅自动更新 + 独立文件存储
  • 多上游并发: UDP / TCP / DoH / DoT / DoH3 / DoQ 六协议, 首答即返, 连接池复用
  • 测速择优(EWMA) + 连接级健康度 + 慢速降级 + 熔断 + 失败降级(fallback) + IPv4 优先(双栈智能)
  • CNAME 链跟踪展开 + 负缓存 + TTL 到期前预取 + 规则级 TTL 覆盖
  • 安全: 0x20 投毒防护 / EDNS0 1232 防分片 / RFC8467 加密查询填充
UPSTREAM + API

上游与观测

upstream.py 六协议连接复用(DoH/DoT/DoQ 连接池) + 熔断; quic_upstream.py 提供 DoH3/DoQ (aioquic 可选, 缺失自动降级); telemetry.py 计数 / 历史 / Top N / 规则命中统计; api.py HTTP JSON API: 查询 / 配置热重载 / 重启 / 规则 CRUD / 一键重测速 / 性能剖析 / metrics, Web 控制台实时展示遥测 / 健康度 / 实时日志筛选 / Map 占用。
