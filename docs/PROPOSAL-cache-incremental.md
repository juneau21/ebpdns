# PROPOSAL：缓存增量落盘（snapshot + incremental）

> **状态：已被取代（superseded）。** 原提案的目标（把"整表周期重写"改成低放大、
> 崩溃丢失窗口有界的落盘）已由当前实现的 **v2 快照 + WAL** 达成；本提案**不再单独实施**。
> 本文保留为设计背景与取舍记录，**仅提案，本版不实现**。

## 1. 原提案要解决的问题

旧落盘是单文件整表 JSON：`cache_save_interval` 到点重写全表。容量越大写放大越高，
且崩溃丢失窗口 = 整个周期（最多一个 `cache_save_interval`）。

原提案提出"快照 + 增量日志"的两层结构，目标是：

- 周期只写增量，避免整表重写；
- 崩溃后能从"快照 + 增量"恢复；
- 不改变缓存的 TTL/淘汰语义。

## 2. 与当前实现的关系

| 原提案要点 | 当前实现 |
|---|---|
| 快照 + 增量日志 | **已实现**：`<base>.snap.<seq>`（EBPCSNP2）+ `<base>.wal.<base_seq>`（EBPCWAL2） |
| 记录级校验 | **已实现**：CRC32C；manifest 52 B 头（v3；v2 的 48 B 头只读兼容）+ 快照 64 B 头 + WAL 32 B 头 |
| 崩溃丢失窗口有界 | **已实现**：WAL 每 1 s `fdatasync` ⇒ ≤ 1 s（`cache_save_interval=0` 例外：只在优雅退出落盘） |
| 不改变缓存语义 | **已实现**：TTL/serve-stale/淘汰策略不变；`persist_ttl` 三段语义保持 |
| 增量 compaction | **已实现**：WAL **2 MiB** 阈值（2.1.37 起；2.1.36 及以前 8 MiB）+ 条目变更比例闸门 12.5% / 1800 s / `min(1800 s, TTL/2)` 按时间触发快照；`MAX_WAL_SEGMENTS=2` |
| 旧格式回滚 | **已实现**：`.v1.bak` + `EBPDNS_CACHE_FORMAT=v1` |

设计细节（文件格式、WAL 总序、退出终态、快照年龄、丢失率口径）见
[`CONVENTIONS.md`](../CONVENTIONS.md) §18 与 [`README.md`](../README.md) §5。

## 3. 未采纳的部分

- **"只写增量、永不写全量快照"**：未采纳。全量快照是恢复的正确性锚点；只靠增量会让
  WAL 无限增长、恢复时间不可控。当前实现用"低频全量快照 + 高频 WAL"折中。
- **"WAL 段无限追加"**：未采纳。`MAX_WAL_SEGMENTS=2` + 阈值 compaction 给磁盘占用设上界。
- **"快照与 WAL 由多个写者并发写"**：未采纳。单线程 actor 是 manifest/WAL 的唯一写者，
  这是 WAL 总序（入队顺序 == seq）的前提。

## 4. 结论

原提案的**目标已由现有 v2 实现覆盖**，无需再按本文实施；本文只作为"为什么是快照+WAL、
而不是纯增量"的决策记录保留。**仅提案，本版不实现。**
